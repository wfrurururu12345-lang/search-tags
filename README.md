
# Search Tags
Учебный проект для построения рекомендательных поисковых тегов маркетплейса на основе истории запросов пользователей.
Система анализирует последовательные поисковые запросы, выбирает 10 наиболее популярных следующих запросов и отображает их на веб-странице.

## Технологии
- Go 1.22
- ClickHouse 25.8
- Docker Compose
- HTML/CSS и Go-шаблоны

## Запуск проекта
Для запуска необходимы Docker, Docker Compose и Go.
Исходный датасет `logs.parquet` находится в папке `data/` и включён в репозиторий.

### 1. Настройка окружения
Создайте файл `.env` на основе примера:
```bash
cp .env.example .env
```
Укажите в `.env` пароль для ClickHouse.

### 2. Запуск ClickHouse

```bash
docker compose up -d
```

### 3. Создание таблицы и загрузка данных

```bash
docker compose exec -T clickhouse clickhouse-client --multiquery < sql/01_create_load.sql
```

Загрузка выполняется один раз для новой базы данных. Повторный запуск добавит те же записи повторно.

### 4. Построение поисковых тегов

```bash
docker compose exec -T clickhouse clickhouse-client --multiquery < sql/02_build_tags.sql
```

### 5. Запуск Go-сервиса

```bash
go mod download
set -a
source .env
set +a
go run .
```

Веб-страница: http://localhost:8080

API: `GET /api/tags?q=платье`

## Хранение и обработка данных
Для хранения данных используется движок `MergeTree`.
Таблица `search_logs` использует `ORDER BY (user_id, timestamp)`, поскольку запросы обрабатываются отдельно для каждого пользователя в хронологическом порядке.
Таблица `tags` использует `ORDER BY (query, rank)` для получения тегов конкретного запроса в порядке популярности.
Правила построения тегов:

1. Запросы приводятся к нижнему регистру, удаляются лишние пробелы.
2. Рассматриваются соседние запросы одного пользователя.
3. Интервал между запросами не превышает 30 минут.
4. Одинаковые запросы исключаются.
5. Подсчитываются уникальные пользователи для каждой пары.
6. Учитываются пары минимум с 5 пользователями.
7. Для каждого запроса выбирается топ-10 тегов.

## Допущения
- В исходном файле не обнаружены NULL и пустые запросы.
- При одинаковом времени события упорядочиваются по тексту запроса.
- При равной популярности теги сортируются по алфавиту.
- Теги пересчитываются пакетным SQL-запросом.
